# AI Ad Creative Workbench

**简体中文** · [English](README.en.md)

**AI 广告创意与素材制作工作台：从投放需求出发，把创意、分镜、审核与视频制作串成一个可回看的流程。**

![工作台首页：项目概览、创作进度与最近成片](assets/screenshots/workbench-home.png)

> 当前以花小猪出行广告为案例，面向 10–20 秒竖屏信息流素材创作。以上及下方图片均截取自实际运行的工作台；示例项目、上传素材和生成视频保留在本地，新安装的工作台从空项目开始。

[功能与页面](#features) · [快速开始](#quick-start) · [模型配置](docs/configuration.md) · [部署与运行](docs/deployment.md) · [常见问题](docs/deployment.md#faq)

## 这个工作台能做什么

把分散在需求文档、提示词、素材文件和视频工具里的创作过程放进同一个项目。每一步保留上下文，方便回看、修改与继续制作。

- **管理创作项目**：查看项目进度、搜索素材项目、继续上次创作、预览最近成片。
- **将需求变成可执行分镜**：从受众、场景、卖点和行动引导，逐步生成创意方向与镜头卡片。
- **让素材制作有依据**：关联产品事实与品牌素材，检查文案、镜头生成方式和口播时长，再进入人工审核。
- **完成生成与交付**：生成或回传镜头，叠加字幕、素材与配音，合成视频，下载成片、封面和结构化创作包。
- **从爆款参考获得创意方法**：导入同平台、同行业的视频链接、脚本与热度快照，拆解结构，勾选建议并追加适配本品牌的新创意。
- **准备单变量测试素材**：围绕开头钩子、CTA 等维度创建创意变体，记录修改范围与测试假设。

渠道配置包含抖音、腾讯广告、快手和微信视频号的素材要求与安全区提示。当前项目负责素材创作，**尚未接入广告账户发布、预算管理或投放效果回传**。

## 六个阶段，一条创作路径

| 阶段 | 在工作台中完成的事 | 主要产出 |
| --- | --- | --- |
| 01 品牌与素材 | 选取品牌规范、参考素材和已确认产品事实 | 创作依据与素材引用 |
| 02 投放需求 | 明确渠道、受众、场景、目标、卖点与 CTA | 结构化 Brief |
| 03 广告创意 | 生成、比较、调整并选择创意方案 | 创意方向与开场钩子 |
| 04 分镜规划 | 编排画面、口播、字幕、时长和素材引用 | 可编辑的分镜卡片 |
| 05 人工审核 | 查看规则检查结果，确认审核清单 | 问题记录与审核状态 |
| 06 生成与合成 | 生成镜头、叠加素材、合成视频、创建变体 | 视频、封面与创作包 |

## 功能与实际页面

### 1. 品牌、素材与事实，共用一份创作依据

品牌规范贯穿后续创作；素材库管理 Logo、产品界面和人物、车辆等参考素材；事实库区分待确认、已确认等状态。文案可以关联事实 ID，便于检查优惠条件和信息来源。优惠卡与 CTA 卡支持程序化生成。

![品牌与素材页面：品牌规范和创作依据](assets/screenshots/brand-assets.png)

### 2. 把投放需求写清楚，再开始生成

按渠道、目标人群和出行场景组织 Brief，填写卖点、表达风格、目标时长与行动引导。渠道提示帮助创作者考虑竖屏构图、字幕和界面遮挡区域。

![投放需求页面：渠道、人群、场景与结构化 Brief](assets/screenshots/creative-brief.png)

### 3. 先比较创意方向，再投入制作

围绕同一份需求生成多个方案，查看核心创意、前 3 秒钩子、用户痛点和事实依据；支持追加方案与局部调整，再选择一个方向进入分镜。

![广告创意页面：多个创意方向及方案内容](assets/screenshots/creative-directions.png)

### 爆款参考与脚本拆解

在“广告创意 → 爆款参考”导入链接、脚本与热度，或批量导入 CSV / JSON。按平台、行业和时间筛选后，由文本模型拆解开场钩子、内容结构、产品呈现与 CTA，给出适配当前项目的复用建议。一键应用会追加新创意，保留来源与已有方案。

当前推荐来自已导入资料，不接入实时榜单、不自动抓取视频。结构示例单独展示；真实拆解与复用需要配置文本模型。完整操作与字段说明见 [爆款参考指南](docs/inspiration.md)。

![爆款参考库：平台和行业筛选、数据来源与脚本资料](assets/screenshots/inspiration-library.jpg)

![真实模型生成的脚本拆解与可勾选复用建议](assets/screenshots/inspiration-analysis.jpg)

### 4. 每个镜头都可以编辑、预览和单独迭代

全局上下文记录人物、车辆、场景与视觉要求。分镜卡片分别管理镜头作用、画面描述、口播、字幕、时长和参考素材，可单独重新生成，减少修改一个镜头时的重复工作。

![分镜规划页面：镜头卡片、预览图、口播与字幕](assets/screenshots/storyboard.png)

镜头提供三种制作方式：

| 方式 | 用途 |
| --- | --- |
| `ai` | 由模型生成场景与人物画面 |
| `overlay` | 生成底片后，用程序叠加字幕、Logo、优惠信息或其他素材 |
| `asset` | 使用已确认素材，例如产品录屏或已审核的画面 |

人物与场景描述、参考图可以帮助保持一致性；生成结果仍需逐镜检查。

### 5. 规则检查与人工审核一起完成

自动检查覆盖事实引用、敏感表达、素材就绪情况、生成方式与口播时长。页面展示阻断项和提醒，并提供部分问题的自动修复；人工再按清单确认画面、文案和品牌表达。

![人工审核页面：自动检查结果与审核清单](assets/screenshots/review.png)

规则检查用于辅助审核。事实库、渠道规范和品牌资料需要持续维护，最终投放内容仍需由业务人员确认。

### 6. 从镜头到成片，保留后续测试空间

支持镜头独立生成、回传和重试。配置视频合成环境后，可叠加字幕、品牌素材与口播配音，输出 1080 × 1920 成片并提取封面。页面也提供单变量创意变体入口，记录测试假设、修改镜头和复用镜头。

![生成与合成页面：已有成片、封面下载与单变量创意测试](assets/screenshots/render-export.png)

“导出包”下载的是 **JSON 创作包**，包含 Brief、创意、事实引用、全局上下文、分镜提示词及变体信息。视频与封面通过各自的下载入口获取。

## 快速开始

### 环境准备

| 依赖 | 说明 |
| --- | --- |
| Node.js | 建议使用 Node.js 22 或 24，需包含 npm |
| FFmpeg | 完整视频合成、字幕叠加和 Mock 占位视频需要；只浏览页面与体验创意流程时可暂不安装 |
| 中文字体 | 中文字幕需要；Windows 会尝试使用微软雅黑，Linux 可配置 Noto Sans CJK |
| 模型服务 | 可选；不配置凭证时，可以先体验 Mock 演示流程 |

### 1. 获取代码并安装依赖

~~~bash
git clone https://github.com/maipeici/ai-ad-creative-workbench.git
cd ai-ad-creative-workbench
npm ci
~~~

### 2. 创建本地配置文件

Windows PowerShell：

~~~powershell
Copy-Item .env.example .env
~~~

macOS / Linux：

~~~bash
cp .env.example .env
~~~

首次体验可保留示例中的空凭证。**已有 `.env` 时直接编辑，不要再次复制覆盖。**

### 3. 构建并打开工作台

~~~bash
npm run build
npm start
~~~

浏览器打开 **http://localhost:8787**。首次启动会自动创建本地项目记录与媒体目录。

Windows 完成依赖安装后，也可以双击**`scripts/start-workbench.cmd`**。启动脚本会检查本地服务；未运行时先构建页面、再启动服务并打开浏览器。

### 4. 创建第一条素材

1. 点击“新建素材项目”，在“品牌与素材”中上传并选择自己的素材，核实产品事实。
2. 填写投放需求，生成并选定创意方案。
3. 生成分镜，检查口播、字幕、时长与参考素材。
4. 完成自动检查和人工审核。
5. 配置模型与 FFmpeg 后生成镜头、合成并下载；也可以先使用 Mock 或手动回传模式体验流程。

没有模型凭证时，创意与分镜使用演示数据，图片使用占位预览。Mock 视频在有 FFmpeg 时生成纯色占位片段，**不是真实 AI 视频**；没有 FFmpeg 时仅返回模拟状态。

## 技术与目录

前端使用 React、TypeScript、Vite 与 Tailwind CSS；后端使用 Node.js 与 Express。Sharp 处理图片，FFmpeg 处理视频，JSON 文件保存本地数据。

~~~text
src/
  client/                 前端源码、组件、创作阶段与样式
  server/                 服务端、模型适配、检查与数据读写
assets/
  public/brand/           页面 Logo 与图标
  screenshots/            README 实际页面截图
config/
  business/               品牌规范、渠道与检查规则
  vite.config.ts          构建与开发服务配置
  tsconfig.json           TypeScript 配置
  tailwind.config.js      样式配置
  postcss.config.js       样式处理配置
data/
  seed/                   首次初始化使用的默认数据
  runtime/                本机项目与媒体，不上传
docs/                     部署、模型配置与贡献说明
scripts/
  start-workbench.cmd     Windows 双击启动入口
  start-workbench.ps1     构建、启动与打开浏览器
tests/                    环境配置与数据初始化测试
~~~

根目录保留 `package.json` 和 `package-lock.json`，统一使用 npm 管理依赖。

开发检查：

~~~bash
npm test
npm run typecheck
npm run build
~~~

运行开发模式：

~~~bash
npm run dev
~~~

开发页面为 **http://localhost:5173**，后端默认为 **http://localhost:8787**。
